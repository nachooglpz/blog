## Generating the Compression Graph

Similar to how an LLM generates text, the compression transformer emits a token conditioned to the current context of the data stream to generate the compression graph on the go.

The token generated by the transformer determines a codec and its set of parameters.
When multi-staged codecs produce child streams, the model generates decisions for each graph, building the graph recursively.

The compressed result is an ordinary OpenZL frame, which is able to be processed by the universal decompressor.

[More info about the inner workings](https://openzl.org/blog/2026-09-24-compression-transformer/).

## Enabling the Compression Transformer

The compression Transformer only works for Numeric types (probably because it is the type several codecs).

### CLI

Just set the compression level to 7 or above.
The following code examples come from [Yann Collet's entry](https://openzl.org/blog/2026-09-24-compression-transformer/).

```bash
./zli compress --profile le-i32 --level 7 examples/getting_started/sample_inputs/era5_ints.bin --output era5_ints.zl
```

### C API

The `ZL_GRAPH_TRANSFORMER_NUMERIC` starting graph needs to be selected **or** the `ZL_GRAPH_NUMERIC` graph needs to be set with [compression level](/notes/000-openzl-levels/) 7 or above.

```C
#include "openzl/codecs/zl_transformer.h"

ZL_Report r = ZL_Compressor_selectStartingGraphID(
        compressor, ZL_GRAPH_TRANSFORMER_NUMERIC);
```

### C++ API

Similar to the C API.

```cpp
#include "openzl/cpp/codecs/Transformer.hpp"

compressor.selectStartingGraph(openzl::graphs::TransformerNumeric::graph);
```
